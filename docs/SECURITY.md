# Execution and data boundaries

Live inference uses only NVIDIA models at the fixed Nebius Token Factory HTTPS endpoint. Requests pin validated public DNS addresses, reject redirects/arbitrary endpoints and enforce time/size limits. Missing credentials or failed calls never turn into a fixture success. Uploaded documents, imported mail and model output are untrusted evidence, never execution authority.

Production requires account authentication, a persistent encryption key and an HTTPS public origin (loopback HTTP is allowed for local verification). Passwords use salted scrypt; opaque session tokens are stored only by hash and expire after 12 hours. Logout revokes the stored session. Stable workspace IDs preserve ownership across logins. Same-origin mutation checks, HttpOnly cookies and login attempt limits protect browser flows. Roles come from the account database, not request bodies or a public role picker. In production, instance-wide execution settings require APPROVER. Model preferences and connected credentials are scoped to the workspace.

Nebius keys and Gmail refresh/access tokens use AES-256-GCM and owner-bound authenticated encryption. API responses never expose the raw credentials. Gmail OAuth state is single-use, actor/workspace-bound and protected by PKCE. Only the fixed Google OAuth and Gmail REST hosts are allowed. Connection configuration and account access are separate from verified live functionality.

Execution is limited to registered tools. Identity rules compare the exact address, including aliases and local-part spelling; project scope, secrets and attachment hashes are checked before transmission. Gmail mailbox provenance does not prove sender authentication, so this adapter does not silently enable automatic sending. The approval preview is bound to the saved draft. Real Gmail requires operator opt-in and post-send verification of SENT label, sender/recipient, subject, body, thread and attachment hashes. This is not recipient delivery/read confirmation. If the outcome is uncertain, the outbox and task are blocked; read-only reconciliation never resends.

Artifacts are prepared in controlled temporary storage, reopened and checked against versioned concrete predicates before commit. Hashes are checked around commit and during download/attachment use. Failed supported file episodes compensate their own generated outputs. Unpublished temporary outputs can be deleted on rejection or verification failure. Previously committed files are deleted only when unmodified and not bound to external actions. Recovery stops and records remaining files on failure. There is no atomic transaction across external services and no recall of delivered mail. One safe repair/replan is allowed per task; external-effect uncertainty is excluded.

The Goal Contract preserves the original goal and versioned completion conditions. Source quotations support selected extracted facts; a matching quote does not establish that an external assertion is true. Unsupported facts require explicit owner review. Tool completion alone does not close the goal. Final confirmation checks the current version, unresolved approvals/mail/file state and committed-file integrity before recording completion and disabling future triggers.

SQLite task/event/operation leases, outbox idempotency and restart recovery prevent blind repeated execution. Run one persistent server/volume and keep the encryption key backed up separately. Closing the tab leaves the worker running; stopping the server pauses it. It does not imply the user's laptop can be powered off while hosting the server there. See [Deployment](DEPLOYMENT.md) for accounts, OAuth, backup and health.

Known scope: one controlled organization instance; workspace isolation is enforced, but this is not an audited multi-tenant SaaS platform. The bundled employee data is a sample, expense processing is a review rather than a payment, and unsupported capabilities stop for human handling. No production secret/account test has been substituted with mock evidence. Keep production and development fixture data separate.
