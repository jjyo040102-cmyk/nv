# ActFlow — 2026-10-11 검증·인계 보고서

기준: Asia/Seoul, 현재 워크스페이스의 미커밋 변경. 공식 대회 분석은 [10월 7일 분석](2026-10-07-actflow-hackathon-review.md), 제출 준비는 [플레이북](actflow-submission-playbook.md)을 참고한다. 이 문서는 10월 7일 구현 상태를 갱신한다.

## 이번 구현

**ActFlow completes work with evidence.** 도구 실행 성공과 사용자의 목표 완료를 구분한다. 계획과 실행 이외에 승인에 결합된 내용, 검증 근거, 실제 복구 결과, 대기 중인 목표를 보존한다.

| 영역 | 현재 동작 |
|---|---|
| 모델 | 고정 Nebius Token Factory 주소와 NVIDIA 모델만 사용. 다른 모델 공급자 SDK·설정·로컬 LLM 경로 제거. 운영 환경에서는 테스트 fixture와 모의 메일 도구 실행을 거부 |
| Gmail | OAuth PKCE, 암호화된 토큰, 선택한 메일 가져오기, 답장 준비, 정확한 수신자·제목·본문·첨부 승인, SENT 조회로 내용·첨부 해시 확인 |
| 불확실한 발송 | 자동 재발송하지 않고 중지. 사용자가 ‘Gmail 발송 결과 다시 확인’을 실행하면 읽기만 수행하고 원래 발송 결과를 검증 |
| 발송 전 실패 | 전송 시도 전에 실패했다고 기록된 초안만 승인을 다시 받을 수 있음. 전송 여부가 불명확한 건에는 적용하지 않음 |
| 완료 조건 | 원래 목표와 요구 작업·파일·메일·선택된 원문 사실을 버전으로 관리. 확인되지 않은 사실은 직접 확인 항목으로 남김. 파일 해시와 최신 상태를 재검사한 후 사용자가 완료 |
| 복구와 재계획 | 지원되는 파일 생성 단계의 실패 시 해당 실행에서 만든 변경되지 않은 파일을 역순 정리. 앞서 확정한 파일도 포함. 변경되었거나 외부 발송에 연결된 파일은 보존하고 복구 실패를 기록. 안전하고 설정된 경우 한 번만 재계획 |
| 지속 업무 | DB 이벤트·예약·작업 잠금·중복 방지. 브라우저 없이 서버 worker가 실행. 연결된 Gmail의 선택한 작업 스레드에 온 답장을 확인 |
| 로그인 | 서버에 저장한 계정·세션, 비밀번호 해시, 로그아웃 취소, 요청 출처 확인. 운영 환경에서 데모 역할 선택과 위조 세션 차단 |
| UI | 작업·승인함·설정 세 메뉴. 작업 화면에서 승인·파일 받기·완료 확인. 이미 확인된 조건과 상세 이력은 접어서 표시. 모바일 가로 넘침 검사 |
| 운영 패키지 | 단일 서버 Docker/Compose, HTTPS 예시, 계정 생성·환경 초기화·백업 명령, 상태 점검, MIT 라이선스와 제출용 소스 ZIP |

메일 제목과 원본 스레드가 어긋나는 답장, 승인 이후 내용 변경, 연결 갱신과 해제의 경합, 위조 요청, 변경된 파일의 잘못된 삭제를 막는 경로도 검사했다. Next.js는 16.3.8로 갱신했고 문서 파서의 취약한 전이 의존성을 교체했다.

화면 확인: [데스크톱 작업 화면](../../data/runtime/release-2026-10-11/ui/desktop-task.png), [모바일 작업 화면](../../data/runtime/release-2026-10-11/ui/mobile-task.png). 테스트 데이터이며 실제 발송·실 모델 실행 증거가 아니다. 390px 모바일에서 승인 후 파일 확인과 목표 완료까지 실행했다.

## 지원 범위와 남은 외부 단계

실제 산출물 검증의 주된 업무는 교육 안내문을 바탕으로 샘플 직원 명단 XLSX와 회신 DOCX를 만드는 것이다. 임의 업무를 모두 실행하거나 원문의 사실 자체를 판정하는 제품은 아니다. 수식 실행·일반 엑셀 계산, Calendar 조작, 실제 결제·전자서명·임의 셸 명령은 지원하지 않는다. Gmail 본문 가져오기는 현재 text/plain을 요구한다.

복구는 이 실행에서 만든 지원 파일에 한한다. 발송한 메일은 되돌릴 수 없다. Gmail SENT 조회는 발송 내용과 제공자의 수락 증거이며 수신·열람 증거가 아니다. Gmail 연결만으로 발신자의 신원이 검증되는 것은 아니므로 실제 답장은 확인을 요구한다. 서버가 꺼져 있으면 자동 확인도 멈춘다.

1. **Nebius:** 계정은 있다고 확인했지만 저장된 키가 없어 크레딧, NVIDIA 모델 접근, 실제 출력 품질을 아직 확인하지 못했다. 설정 화면의 실제 연결 검사 후 합성 업무로 실측한다.
2. **Gmail:** OAuth 클라이언트와 연결된 메일함이 없어 실제 Google 동의·갱신·발송·조회·답장 Wake는 계정에서 확인해야 한다. 연결 구현과 실패 처리는 mock으로 검사했다.
3. **호스팅:** 배포 패키지는 준비했다. 선택한 서버에서 Docker 빌드, HTTPS, 볼륨, 상시 worker, 외부 접속을 확인해야 한다. 이 Windows 환경에는 Docker 엔진이 없어 컨테이너 빌드를 실행하지 않았다.
4. **제출:** 공개 저장소·심사 접근 URL·영어 3분 미만 영상·실사용 기술 피드백·기존 개발 이력 공개와 최종 Devpost 제출이 남아 있다. 영상은 [녹화 대본](../COMPETITION_DEMO.md)을 준비했으며 실제 녹화·게시를 하지는 않았다.

실계정·호스트 정보가 없는 항목을 완료로 표시하지 않았다. 지금 이어서 사용할 문서는 [배포와 Gmail 연결 안내](../DEPLOYMENT.md)다. 현재 사용자 데이터베이스를 테스트용으로 덮어쓰거나 저장된 비밀값을 출력하지 않았다.

## 전달 파일

이전 ZIP은 `data/runtime/release-2026-10-11/source-before.zip`으로 보존했다. 현재 변경은 커밋·원격 업로드·공개 배포하지 않았다. 검토와 외부 설정을 마친 후 이 소스를 제출 빌드의 기준으로 사용한다.
